## 2. Defects Found & Fixed

### DEF-001 — P1 · Stored XSS via JSON-LD script breakout · **FIXED & VERIFIED**

- **Where:** `src/components/seo/json-ld.tsx:9` rendered `JSON.stringify(data)` into `<script type="application/ld+json">` with **no `<` escaping**.
- **Sink path:** `src/app/(website)/blog/[slug]/page.tsx:34` — when a post has no `excerpt`, `generateArticleSchema` uses `post.content.substring(0, 160)` as the JSON-LD description, so author-controlled HTML (including `</script>`) lands inside a live script element.
- **Impact:** any content in the first 160 chars of a post body could terminate the JSON-LD script early and inject HTML/script into the public blog page for every visitor.
- **Evidence:** `evidence/xss-evidence-prefix.txt` (pre-fix server HTML with raw `<script>window.__qa=` payload) and pre-fix test **QA-0506 = FAIL** in `evidence/harness2-prefix-vulnerable.json`.
- **Fix:** escape `<` → `\u003c` in `json-ld.tsx` (valid JSON, harmless to JSON-LD consumers):
  ```ts
  const json = JSON.stringify(data).replace(/</g, "\\u003c");
  ```
- **Verification:** post-fix production build `fY5dmV1nclzuklXgPvzUw`; **QA-0506 = PASS** (`rawScript=false, rawOnerror=false`) in `evidence/harness2-final.json`. tsc/lint/jest/build all re-run green.
- **Deployment status:** code fixed locally, build green — **NOT committed/deployed** (awaiting commit instruction).
